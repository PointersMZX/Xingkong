# 排查问题

## Daemon 一直未连接

先检查：

1. 是否已经执行 Root 启动或 Shell 启动。
2. Root 授权是否被拒绝。
3. Shell 命令是否来自当前 App 页面。
4. 执行命令后是否回到 App 等待几秒。
5. App 是否被系统限制后台运行。

如果仍未连接，优先重新执行 App 当前显示的 Shell 命令。  
不要使用旧版本、旧设备或截图里的命令。

## Power 为 0 或方向反了

处理顺序：

1. 启动 Daemon。
2. 拔掉充电器，让设备进入放电状态。
3. 重新执行自动探测。
4. 检查是否需要串联双电芯。
5. 必要时手动调整电流校准。

不要先调整 FPS、悬浮窗或记录设置。  
Power 基础口径不正确时，这些页面只会展示错误结果。

## 悬浮窗打不开

先检查：

1. 系统悬浮窗权限是否开启。
2. Daemon 是否连接。
3. 当前系统是否限制后台弹窗。
4. 是否在录制或采样状态下关闭了必要组件。

如果只有某个字段显示 `--`，说明是该数据源不可用，不一定是悬浮窗权限问题。

## FPS 记录启动失败

常见原因：

- Daemon 未连接。
- 当前没有有效前台 App。
- 当前前台 App 是 Metric 自己。
- 记录数据通道不可用。
- 已有记录会话正在运行。

处理方式：

1. 切到要记录的目标 App。
2. 确认 FPS recorder 已开启。
3. 回到目标 App 后再开始记录。
4. 如果提示数据通道不可用，重启 Metric Daemon。

## FPS 记录中途停止

常见停止原因：

- 前台 App 变化。
- 计时结束。
- 用户手动停止。
- Daemon 断开。
- 目标 App 退出。
- App 后台被系统清理。

如果停止后已经保存，可以在 FPS Records 中查看。  
如果没有记录，先检查停止提示和日志。

## GPU 频率不可用

GPU 频率受权限和设备节点影响。  
如果普通 Shell 场景无法读取，可能需要 Helper 或 Root 环境。

先检查：

- 当前 Daemon 启动 UID。
- Helper 是否安装并可用。
- 设备是否暴露 GPU 频率节点。

## 页面数据部分为空

部分字段为空不等于整个功能失败。

常见原因：

- 当前设备没有对应内核节点。
- 权限不足。
- Daemon 刚启动，数据还没刷新。
- 当前功能未开启专项采样。
- 该记录本身没有对应样本。

优先判断是“单个字段不可用”还是“Daemon 未连接”。  
前者看对应功能页，后者先回到激活页处理启动。
