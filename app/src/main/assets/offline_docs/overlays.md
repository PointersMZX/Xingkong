# 悬浮窗

## 入口

从顶层导航进入悬浮窗管理。  
如果系统悬浮窗权限未开启，Metric 会先显示权限引导。

## 使用前检查

开启悬浮窗前确认：

- Metric Daemon 已连接。
- 系统悬浮窗权限已允许。
- 当前设备允许 App 在其他应用上层显示。

如果 Daemon 断开，悬浮窗可能停止刷新。  
这种情况应回到 App 内重新启动服务。

## 负载监视器

负载监视器适合在其他 App 上方观察整体负载。

常见数据：

- CPU 占用和频率。
- GPU 占用和频率。
- RAM / DDR。
- FPS。
- Power。
- 电池温度。

部分字段不可用时会显示占位值。  
这通常和设备权限、内核节点或 Helper 状态有关，不代表整套悬浮窗失效。

## 线程监视器

线程监视器用于查看目标进程的线程负载。

常见字段：

- CPU%：线程瞬时 CPU 占用。
- CPUS：线程运行或允许运行的核心范围。
- TID：线程 ID。
- COMM：线程名。

关闭线程监视器会停止对应线程采样。  
如果 FPS 记录正在进行，FPS 记录所需的数据链路不应被关闭。

## FPS 记录器

FPS 记录器是 FPS 记录的悬浮入口。

它负责：

- 展示当前 FPS。
- 开始记录。
- 停止记录。
- 显示当前记录状态。

历史记录和图表分析不在悬浮窗里完成。  
这些内容在功能页的 FPS Records 中查看。

## 常见问题

### 点开关后没有悬浮窗

先检查：

1. 悬浮窗权限是否开启。
2. Daemon 是否连接。
3. 当前系统是否限制后台弹窗或悬浮窗。

### FPS 显示为 `--`

说明当前帧率来源不可用。  
可以到设置页调整 FPS sampling，或切换到能提供帧率数据的前台 App 后再试。

### Power 看起来不对

先处理 [电池与功率校准](calibration.md)。  
悬浮窗只是展示 Power，不负责独立校准。
