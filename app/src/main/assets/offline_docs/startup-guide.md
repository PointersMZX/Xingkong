# 启动服务与激活页

## 先区分两个页面

- 首次引导：首次进入且引导未完成时出现，用来完成启动服务和校准。
- 激活页：Metric Daemon 未连接时出现，提供启动入口并等待服务连接。

首次引导不是连接状态页。  
即使引导已经完成，只要 Daemon 没有连接，App 仍会显示激活页。

## 首次引导里有什么

首次引导包含三页：

1. 介绍页：确认 Metric 的主要用途。
2. 启动服务页：Root 启动或复制 Shell 命令。
3. 校准页：自动探测、电流校准、串联双电芯。

首次引导不包含：

- 独立 Daemon 介绍页。
- 无障碍启动。
- 单独的准备就绪页。

## 激活页什么时候出现

常见情况：

- 首次引导完成后，Daemon 仍未连接。
- App 被系统回收后重新打开，正在等待 Daemon 重新推送 Binder。
- Daemon 启动失败。
- Daemon 被停止、崩溃或被系统清理。
- App 升级后旧 Daemon 退出，新 Daemon 尚未连回。

> [!NOTE]
> 激活页不会假装连接成功。只有 App 实际收到 Daemon Binder 后，才会进入主界面。

## Root 启动

Root 启动适合已经 Root 的设备。

操作步骤：

1. 点击 Root 启动。
2. 在 Root 授权弹窗中允许。
3. 等待服务状态变为已连接。

如果 Root 启动失败：

- 检查 Root 管理器是否拦截。
- 确认 Metric 没有被加入拒绝列表。
- 改用 Shell 命令启动。

## Shell 命令启动

Shell 启动适合 ADB Shell 或设备本地终端。

操作步骤：

1. 在 App 内复制启动命令。
2. 打开 ADB Shell 或本地终端。
3. 粘贴并执行命令。
4. 回到 App 等待连接。

命令路径来自当前安装包，不同版本、不同安装位置可能不同。  
不要把旧设备上的命令复制到另一台设备使用。
