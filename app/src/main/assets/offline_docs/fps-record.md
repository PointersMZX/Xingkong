# FPS 记录

## 入口分工

- 悬浮窗管理 > FPS recorder：开启当前 FPS 记录器。
- FPS 记录器悬浮窗：开始或停止一次记录。
- 功能页 > FPS Records：查看历史记录。
- 记录详情页：查看图表、统计和线程负载。

## 开始记录前

开始前先确认：

- Metric Daemon 已连接。
- 当前前台 App 是你要记录的目标。
- 前台 App 不是 Metric 自己。
- 悬浮窗权限已开启。

如果目标不可用，Metric 会直接提示启动失败。  
不要把这种失败当成记录文件损坏。

## 开始一次记录

推荐流程：

1. 打开目标 App。
2. 回到 Metric 开启 FPS recorder。
3. 切回目标 App。
4. 点击 FPS 记录器中的记录按钮。
5. 需要定时结束时，选择记录时长。
6. 结束后到 FPS Records 查看结果。

如果设置里开启了“点击胶囊停止记录”，录制中点击小胶囊会直接停止并保存。

## 记录会保存什么

一次 FPS 记录会保存：

- FPS。
- Frame Time。
- Jank。
- CPU 占用。
- CPU 频率。
- CPU Cycles。
- GPU 占用。
- GPU 频率。
- DDR 频率。
- Power。
- 电量。
- 温度。
- 线程负载。

部分数据源不可用时，会保留异常状态或空数据，不会生成假样本。

## 记录为什么会停止

常见停止原因：

- 手动停止：用户主动点击停止。
- 计时结束：到达选择的记录时长。
- 前台应用发生变化：目标 App 切换，记录自动结束并保存。
- Daemon 异常断开：数据源断开，记录结束。
- 目标应用丢失：被记录 App 退出或不可识别。
- App 后台被杀：App 进程被系统清理。
- 异常停止：其他错误。

停止后如果保存成功，会出现在 FPS Records 历史列表。

## 历史列表

FPS Records 页面用于管理历史记录。

你可以在这里：

- 查看设备概览。
- 查看记录列表。
- 打开记录详情。
- 删除记录。

历史列表为空时，说明当前设备还没有保存过 FPS 记录。

## 详情页怎么读

详情页重点看三类信息：

1. FPS 统计：最大、最小、平均、1% Low、5% Low。
2. 帧时间与 Jank：判断卡顿尖刺。
3. 设备状态：CPU、GPU、DDR、Power、温度、电量。

图表中的 `--` 或空段表示对应时间点没有有效数据。  
这比补假数据更适合定位问题。

## 线程负载详情

如果记录包含线程样本，可以进入线程负载详情。

常见信息：

- 线程平均负载。
- 线程最大负载。
- 主要运行核心。
- 迁移次数。
- Affinity 变化。
- 核心分布。

这些信息适合用来判断某个线程是否长期跑在不合适的核心上。

## 导出和长截图

详情页支持：

- 保存长截图。
- 导出记录。

失败时 App 会显示错误提示。  
常见原因包括存储权限、目标目录不可写或记录数据缺失。
